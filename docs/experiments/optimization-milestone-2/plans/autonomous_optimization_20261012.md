# Autonomous optimization sequence

User authorization: work autonomously and sequentially through obvious candidates, update the tracker after each step, preserve independently selectable features, commit each change, and run full sampler validation/profiling for promising combinations. This supersedes the previous review-only restriction. Preserve the published `optimization-milestone-1` baseline, original legacy engine, fPS/variance branches, and the exclusion of abandoned blockwise/debug designs. No concurrent sampler fits or large parameter grids.

1. Create an isolated dependent worktree. Profile representative longer T2D inner fits with bounded replay/capture. Establish where inner time is spent before choosing kernels.
2. Introduce independent feature switches and preset-compatible overrides, with explicit validation of combinations and documented inactive prerequisites where needed. Keep all existing CLI presets and legacy default.
3. Evaluate inner conditional compilation/fusion, fixed-array/mask preparation, incremental residual maintenance, and the profile-identified direct prefilter quadratic forms in that evidence-driven order. Verify fixed-input/random-draw agreement, edge cases and full inner fits. Keep each change separate and switchable. Reject candidates early if their cost exceeds benefit.
4. Assemble a promising arithmetic combination and run serial full 500-budget T2D validation plus a separate representative profile. Reuse the completed milestone baseline where configuration/measurement provenance permits; label timing comparability limits. Extend to a bounded NAFLD pair for a retained combination. Do not repeat the 104-minute legacy fit unnecessarily.
5. Evaluate the smallest inference changes separately: reduced inner effort and the existing conditional-mean approximation. The target audit rules out a direct Gaussian VI substitution without a separate compatible-target derivation. Use reference inner problems and bounded outer checks before full validation. Treat approximation/uncertainty differences explicitly. Review persistent joint inference, support moves and broader approximations against the requirement for a defined production target; document unready designs rather than silently substituting a different model.
6. At each decision update `plans/optimization_tracker.md` and a dated log, commit atomic tested changes, and push worthwhile checkpoints under existing authorization. Preserve rejected candidate code behind off-by-default switches only when it is safe and useful; otherwise retain the rejection evidence without enabling it.
7. Finish when the obvious bounded candidates have been tested or ruled out with concrete evidence. Record full timing, memory, priors/uncorrected/corrected beta agreement, diagnostics and implementation limitations. Tag a further milestone only if justified; never assert improved convergence from budget completion or deterministic stability.

Experiment budget discipline: one fit at a time; five-minute caps for initial profiles and kernel experiments; up to 30 minutes per optimized full fit unless evidence justifies more. Prefer paired fixed-input kernel timing and exact update checks before new full sampling. No arbitrary repetitions solely to obtain favorable timings.
